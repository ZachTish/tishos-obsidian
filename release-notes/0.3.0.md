# TishOs 0.3.0 — Native food and workout commands

The Obsidian command palette can now open the native TishOS food picker,
barcode scanner, and Workouts workspace. The existing customizable **Open
TishOS app** command remains available.

| Command | Native link |
| --- | --- |
| Log food | `tishos://food/log` |
| Scan food barcode | `tishos://food/log?mode=scan` |
| Log workout | `tishos://workout/log` |

The complete command set requires native TishOS **0.39.10 (303) or newer**.
Configure its vault and logging there. Earlier app builds may support food
logging but do not handle the workout link. The plugin's optional App link is only used by **Open TishOS
app**. Built-in logging commands need no additional plugin settings. They use
the vault selected in the native app, which may differ from the open Obsidian
vault. They do not pass note content, vault paths, credentials, or write requests.
The native app owns permissions, unsaved drafts, workout sessions and explicit
save actions. Opening Workouts does not start or save a workout.

The runtime change adds three entries to the existing command list. No runtime
dependency, setting, migration, view, index, listener, timer, vault scan, note
read/write, or background network work was added. Health and GCM are not required.
Minimum Obsidian version remains 1.0.0; desktop and mobile are permitted.

## Validation

- All 13 declared tests pass with no skips, followed by a separate final build.
- Tests execute the real command callbacks with a guarded host that rejects
  vault access, network calls and timers. They cover exact route dispatch with
  blank/custom settings, repeated invocations, existing custom-link validation,
  save failures and lifecycle behavior.
- The final bundle was deployed to Obsidian Plugin Test Vault on Obsidian 1.15.0.
  Two load/unload cycles registered all four commands, dispatched their exact
  URLs through Obsidian's command dispatcher, and removed the commands on unload.
- External launching was intercepted in installed QA: no native camera,
  workout, provider or note-writing flow was started. This verifies the plugin
  dispatch boundary, not physical-device handoff or native action completion.
- Test-vault core/community settings remained byte-identical. No TishOs private
  data file was created, and the original disabled state was restored.
- No settings layout or controls changed.
